# Library Documentation

## FastAPI (0.115.12)

FastAPI is a modern, high-performance Python web framework designed for building REST APIs with minimal code. It's built on top of Starlette for the web framework part and Pydantic for data validation. FastAPI automatically generates interactive API documentation (Swagger UI and ReDoc) from your code, making it easy to test endpoints. It supports async/await syntax for high-performance asynchronous operations, which is crucial for I/O-bound tasks like database queries and file uploads. The framework uses type hints extensively, providing automatic request validation and response serialization. FastAPI is lightweight yet powerful, making it ideal for production deployments while maintaining developer productivity. In this project, FastAPI handles all REST API endpoints for attendance, face recognition, students, enrollments, and admin management, routing requests to appropriate handlers and returning JSON responses.

## Uvicorn (0.34.0 with standard extras)

Uvicorn is an ASGI (Asynchronous Server Gateway Interface) web server implementation written in Python. It serves as the runtime that actually runs your FastAPI application and handles incoming HTTP requests. Uvicorn is extremely fast and efficient, supporting concurrent request handling through async operations. The `[standard]` extra includes additional dependencies like uvloop and httptools, which provide performance optimizations. When you run `uvicorn app.main:app --reload`, this command starts the Uvicorn server, which listens on a port (default 8000) and forwards requests to your FastAPI application. Uvicorn automatically manages worker processes and can be scaled horizontally for production use. It supports hot-reloading during development, meaning code changes automatically restart the server without manual intervention. In production on Heroku, Uvicorn runs as specified in the Procfile, binding to the PORT environment variable provided by the platform.

## SQLAlchemy (2.0.40)

SQLAlchemy is a powerful Object-Relational Mapping (ORM) library that abstracts database interactions into Python objects. Instead of writing raw SQL queries, you define Python classes that represent database tables, and SQLAlchemy handles the translation to SQL. It supports multiple database backends including MySQL, PostgreSQL, SQLite, and others, making your code database-agnostic. SQLAlchemy 2.x introduced significant improvements including better type annotations, improved async support, and clearer API patterns. The ORM allows you to define relationships between tables (one-to-many, many-to-many) using Python syntax, making data manipulation intuitive. It handles query building, result mapping, and transaction management automatically. In this project, SQLAlchemy models represent students, enrollments, attendance records, face templates, and admin data, allowing the application to perform CRUD operations without writing manual SQL.

## Pydantic (2.11.3)

Pydantic is a data validation and serialization library that uses Python type hints to enforce data structure correctness. When API clients send JSON data, Pydantic automatically validates that the data matches the expected schema defined in your request models. If validation fails, Pydantic provides clear error messages about what went wrong. Beyond validation, Pydantic handles type coercion (converting strings to integers, for example) and serialization (converting Python objects back to JSON for API responses). It supports complex nested data structures, custom validation logic, and field constraints (like minimum/maximum values). Pydantic integrates seamlessly with FastAPI, automatically generating API documentation based on your models. In this project, Pydantic schemas define the structure of attendance records, enrollment data, student information, and API request/response payloads, ensuring data consistency throughout the application.

## Email-Validator (2.2.0)

Email-Validator is a specialized library for validating and normalizing email addresses according to RFC 5321 and RFC 5322 standards. It goes beyond simple regex pattern matching by checking the actual structure and format of email addresses. The library can detect common typos (like "gmial.com" instead of "gmail.com") and normalize email addresses to a standard format. It validates the local part (before @) and domain part (after @) separately, ensuring both conform to email standards. Email-Validator also supports checking whether a domain has MX records, though this can be disabled for performance. In this project, whenever admin users or students are created/updated with email addresses, Email-Validator ensures the email format is correct and properly formatted, improving data quality and preventing invalid emails from being stored.

## Python-Dotenv (1.1.0)

Python-Dotenv loads environment variables from a `.env` file into your Python application at runtime. Environment variables are a secure way to store sensitive configuration like database credentials, API keys, and allowed origins without hardcoding them into your source code. Using a `.env` file during development allows each developer to have their own database connection settings without affecting others. The library reads the `.env` file and populates `os.environ` with the variables, which your application can then access. This approach follows the Twelve-Factor App methodology, separating configuration from code. In production, you don't use a `.env` file; instead, you configure environment variables directly in your hosting platform (Heroku Config Vars). In this project, `DATABASE_URL` and `ALLOWED_ORIGINS` are loaded from the `.env` file, allowing flexible deployment across different environments.

## PyMySQL (1.1.1)

PyMySQL is a pure Python MySQL client library that enables Python applications to connect to and communicate with MySQL databases. Unlike MySQLdb (which requires C extensions), PyMySQL is written entirely in Python, making it easier to install and more portable across platforms. PyMySQL handles the MySQL protocol, establishing connections, executing queries, and retrieving results. It supports both synchronous and asynchronous operations, though typically used synchronously with SQLAlchemy. The library manages connection pooling, transaction handling, and error reporting. PyMySQL works seamlessly with SQLAlchemy as the database driver, specified in the `DATABASE_URL` as `mysql+pymysql://`. In this project, PyMySQL is the bridge between SQLAlchemy and your MySQL database server, handling all low-level database communication for storing and retrieving attendance, student, and enrollment data.

## Cryptography (>=42.0.0)

The Cryptography library provides cryptographic primitives and protocols for secure data handling. It offers various encryption algorithms (AES, RSA), hashing functions, digital signatures, and secure password hashing. While not directly used in the visible API code, cryptography is often a dependency of other security-related libraries. It's included here as a dependency of packages like python-jose (if used for JWT tokens) or to handle sensitive operations securely. The library uses OpenSSL under the hood but provides a Pythonic API for cryptographic operations. In a production authentication system, cryptography would handle password hashing, token generation, and encryption of sensitive data. The `>=42.0.0` version specifier ensures you have recent security patches, as cryptography frequently updates for new vulnerabilities.

## Face-Recognition (1.3.0)

Face-Recognition is a Python library built on top of dlib's face recognition models for detecting and encoding faces in images. It simplifies face recognition tasks by providing high-level functions for detecting faces in an image and computing 128-dimensional face embeddings (mathematical representations of faces). These embeddings can be compared to determine if two faces belong to the same person. The library is pre-trained on millions of faces, requiring no training data for typical use cases. It can identify multiple faces in an image and handle various face angles and lighting conditions reasonably well. In this project, Face-Recognition is central to the attendance system: it detects faces in student enrollment images, generates embeddings for each student, and during attendance capture, compares live face embeddings against stored templates to identify students.

## NumPy (2.2.5)

NumPy is the fundamental package for numerical computing in Python, providing support for arrays and matrices along with mathematical functions. It's essential for scientific computing, data analysis, and machine learning workflows. NumPy arrays are much more efficient than native Python lists for numerical operations, especially with large datasets. The library provides linear algebra operations, Fourier transforms, statistical functions, and random number generation. When Face-Recognition computes face embeddings (128-dimensional vectors), NumPy handles the mathematical operations. When comparing face embeddings during recognition, NumPy calculates distances between vectors. NumPy is also used for image manipulation and numerical operations on image data. In this project, NumPy powers the mathematical computations behind face encoding/recognition and handles efficient numerical operations throughout the system.

## Pillow (11.2.1)

Pillow is a Python imaging library that provides tools for opening, manipulating, and saving image files in various formats (JPEG, PNG, BMP, GIF, etc.). It offers image filtering, resizing, rotation, cropping, and color space conversions. Pillow can read image metadata and perform per-pixel operations efficiently. The library is commonly used for image preprocessing before machine learning tasks. In conjunction with Face-Recognition, Pillow handles image loading, resizing to appropriate dimensions, and format conversion before face detection. When students upload enrollment images or teachers capture live attendance photos, Pillow processes these images to ensure they're in the correct format and size. It can also generate thumbnails or resize images for storage optimization. In this project, Pillow prepares images for face recognition by handling format compatibility and image transformations.

## Python-Multipart (0.0.20)

Python-Multipart is a library that enables parsing of multipart form data, which is necessary for handling file uploads in web applications. When clients send files through HTTP POST requests (like uploading enrollment face images), the data is encoded as multipart/form-data. FastAPI uses Python-Multipart to parse these requests and extract file data alongside other form fields. Without this library, FastAPI wouldn't be able to properly handle file uploads. The library handles the parsing of boundary delimiters, content-type headers, and extracting file contents from the request body. It supports multiple file uploads in a single request and can handle both files and regular form fields simultaneously. In this project, Python-Multipart enables the face-templates/encode endpoint to accept multiple image files for enrollment and allows any file upload functionality in the attendance system.
